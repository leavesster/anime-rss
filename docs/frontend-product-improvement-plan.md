# 前端产品改进计划

更新日期：2026-07-23

## 目标

把当前前端从“领域数据与运行信息的展示界面”收敛为普通用户可以理解、判断并完成操作的追番产品。改进重点依次是：消除误操作和假警报、补齐操作闭环、解释自动决策、最后整理信息架构与移动端体验。

## 状态说明

- `待处理`：尚未开始。
- `进行中`：已有未完成的代码或设计工作，接手前先查看该项备注和工作区状态。
- `已完成`：代码和针对性测试已经完成。
- `已验证`：除针对性测试外，已经通过完整前端或项目验证。
- `受阻`：存在需要产品决策、外部环境或其他任务先完成的依赖。

每完成一项，应立即更新本文件中的状态、完成内容、验证命令和提交。不要等到整个计划结束后一次性补记。

## 实施顺序

| 编号 | 优先级 | 状态 | 改进项 | 完成标准 |
| --- | --- | --- | --- | --- |
| FP-01 | P0 | 待处理 | 概览页只读加载 | 打开、切回或自动重试概览页不会调用播出同步写接口；用户仍可通过明确操作同步日历，并能看到同步进度或错误。 |
| FP-02 | P0 | 待处理 | 修正“需要处理”的异常口径 | 正常但不适合自动识别的 RSS 条目不再计入系统失败；真正失败、待确认和已忽略状态有清晰边界。 |
| FP-03 | P0 | 待处理 | 下载器未配置时阻止误提交 | 未配置 qBittorrent 时不能创建注定无法执行的任务，并提供直达配置的行动入口；连接中断与未配置有不同提示。 |
| FP-04 | P1 | 待处理 | 解释版本选择结果 | 每集能看出当前赢家、等待状态、淘汰原因及生效规则来源；移动端保留必要决策信息。 |
| FP-05 | P1 | 待处理 | 拆分识别状态语义 | 不再同时出现“已定位”和“未匹配到动画”；标题解析、集数解析、动画关联、人工确认分别表达。 |
| FP-06 | P1 | 待处理 | 调整追番页信息层级 | 当前追番、待处理剧集和最近选择先于 RSS 自动发现内容；发现区默认收起或独立分页。 |
| FP-07 | P1 | 待处理 | 将通知改造成行动队列 | 通知包含对象、行动链接和可读状态；支持过滤、批量已读及同类聚合，首页与通知数量口径可解释。 |
| FP-08 | P1 | 待处理 | 修正“可靠”等误导性文案 | `automation_eligible` 统一表达为“可自动处理 / 仅可人工处理”，相关说明不暗示内容安全。 |
| FP-09 | P1 | 待处理 | 移除伪语言选项 | 在完整国际化上线前不再提供无效的 English 选项；已有 `en` 配置有明确兼容行为。 |
| FP-10 | P1 | 待处理 | 修正登录状态与恢复提示 | 普通未登录、会话过期、首次设置分别显示真实原因；忘记管理员密码时能找到安全恢复指引。 |
| FP-11 | P1 | 待处理 | 分离用户运行状态与高级诊断 | 默认页面使用产品语言并突出可行动异常；内部任务名、事件、UUID 收进高级诊断；手动运行说明执行范围。 |
| FP-12 | P2 | 待处理 | 大列表与移动端收敛 | 主要大列表具备分页或渐进展开、筛选和异常优先；移动端一级导航不超过五项，候选卡不丢失决策信息。 |
