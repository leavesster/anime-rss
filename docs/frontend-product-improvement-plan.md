# 前端产品改进计划

更新日期：2026-07-23

## 目标

把当前前端从“领域数据与运行信息的展示界面”收敛为普通用户可以理解、判断并完成操作的追番产品。改进重点依次是：消除误操作和假警报、补齐操作闭环、解释自动决策、最后整理信息架构与移动端体验。

## 状态说明

- `待处理`：尚未开始。
- `进行中`：已有未完成的代码或设计工作，接手前先查看该项备注和工作区状态。
- `已完成`：代码和针对性测试已经完成。
- `已验证`：除针对性测试外，已经通过完整前端或项目验证。
- `受阻`：存在需要产品决策、外部环境或其他任务先完成的依赖。

每完成一项，应立即更新本文件中的状态、完成内容、验证命令和提交。不要等到整个计划结束后一次性补记。

## 交付记录

### FP-01 概览页只读加载

- 状态：已完成
- 完成内容：新增只读的日历概览查询；概览页加载、切回和查询重试不再触发同步。原刷新图标改为明确的“同步播出信息”操作，并显示进行中、成功和失败反馈。
- 涉及：`web/src/features/dashboard/DashboardPage.tsx`、`web/src/generated/api/client.ts`、`web/tests/dashboard-schedule.test.tsx`。
- 验证：`npm run test -- dashboard-schedule.test.tsx`、`npm run typecheck`、`npm run lint`。
- 提交：`fix(web): keep dashboard schedule loading read-only`。

### FP-02 修正“需要处理”的异常口径

- 状态：已完成
- 完成内容：未匹配识别结果增加内容类型；合集、剧场版和特别篇保留在识别列表但不再进入运行失败队列。无集数的 BDRip 标题归类为合集。运行聚合增加“失败 / 需要确认”语义，首页和运行页分别以红色和黄色呈现。
- 涉及：识别 DTO、运行聚合与 API 契约、首页、运行页、状态样式及其测试。
- 产品约束：剧场版、合集、旧番整季等非目标资源可以保留，但不能默认等同于系统失败。
- 验证：后端针对性测试 10 项通过；前端针对性测试 6 项通过；`make lint`、`make typecheck`、`make openapi-check`、前端 lint 和类型检查通过。
- 提交：`fix(operations): separate failures from recognition confirmations`。

### FP-03 下载器未配置时阻止误提交

- 状态：已完成
- 完成内容：种子页读取 qBittorrent 配置；未配置时展示引导、禁用提交并直达下载配置。后端手动提交接口增加同样的配置前置条件，防止绕过前端创建无执行条件的任务。配置存在但暂时离线时仍允许排队。
- 涉及：种子页、下载服务与 HTTP 边界、模块说明和前后端测试。
- 验证：后端手动提交集成测试 1 项、前端交互测试 2 项通过；前后端 lint、类型检查通过。
- 提交：`fix(downloads): require configuration before manual submission`。

### FP-04 解释版本选择结果

- 状态：已完成
- 完成内容：候选页复用订阅规则预览、单集状态和真实决策记录，为每个版本展示已选择、当前首选、等待首选、需要确认、硬性排除或首个排序败因，并标明全局规则或单独规则。解释位于候选标题区域，窄屏不会隐藏。
- 涉及：`web/src/features/recognition/CandidatesPage.tsx`、候选样式和识别页面测试。
- 验证：候选页 5 项交互测试、前端 lint 和类型检查通过。
- 提交：`feat(web): explain candidate selection outcomes`。

### FP-05 拆分识别状态语义

- 状态：已完成
